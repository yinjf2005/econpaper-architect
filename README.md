## 一、为什么经济学论文需要一个"决策内核"，而不是一个"生成器"

一个常被忽略的事实是：大多数经济学论文写不好，问题不在"写"，而在"写之前"。模型选错了族——用断点回归去处理本该用交叠 DID 的数据；识别假设没论证——通篇因果结论却拿不出平行趋势或外生冲击；格式失范——三线表做成了网格表、正文引用与参考文献对不上。这些根源都坐落在动笔之前，不是一个"把句子写漂亮"的工具能补救的。

这正是 EconPaper Architect（经济论文架构师）的设计起点。它不把自己定位成生成器，而定位成决策内核：陪使用者把每一个前置决策做对，再把做对的决策翻译成结构完整、模型适配、逻辑自洽、格式规范的论文。它的全部知识，来自一份底本——《经济论文撰写指引》。

本文分三层展开：先看这份指引自身的底层结构，再看 skill 如何把结构变成可执行的决策逻辑，最后交代这套能力是怎么被造出来的。

## 二、《经济论文撰写指引》的底层结构：一份按"决策阶段"组织的知识体

指引不是一本写作手册，而是一张"从现象到成稿"的决策地图。它按"判断类型 → 选模型 → 选逻辑 → 定风格"推进，全文可归为六大板块，彼此不是并列章节，而是前后咬合的漏斗。

**第一层，类型与模板。** 动笔前先判定论文属于哪一型（实证 / 理论 / 综述 / 政策 / 混合），再落到模板 A/B/C。这一步决定了后面所有分支的入口，类型判错，后续全部偏移。

**第二层，34 个模型与五大家族。** 指引把可用的计量与结构模型收成 34 个，归为五大家族：因果识别与政策评估（DID 家族、IV、RDD、PSM、合成控制、事件研究、面板固定效应）、机器学习与异质效应（DML、因果森林）、结构模型（BLP、动态离散选择、CGE、DSGE、ABM）、宏观与时序（VAR、DSGE、ABM）、以及专题与混合模型。每个模型都带"核心问题 / 关键假设 / 适配 / 不适配 / 典型替代"五字段，不是名词表，而是可比对的选择集——你看到的不是"有哪些方法"，而是"在什么条件下该用哪一个、不该用哪一个"。

**第三层，§3.6 六层决策树。** 这是指引的主干逻辑，把"选模型"从拍脑袋变成可执行的六层筛选器：研究目标决定模型家族，识别来源决定具体模型，数据条件修正模型，推断目标确认模型，关键假设进入检验，最后落到稳健性方案。六层逐层收窄，每一步都引用明确节号。举一个微型算例：研究目标是"评估一项政策的因果效应" → 家族锁定因果识别；识别来源是"政策在不同地区分批落地" → 具体模型指向交叠 DID；数据条件是"仅有两期面板" → 模型收窄为经典 DID 而非事件研究；推断目标是"平均处理效应" → 确认；关键假设是"平行趋势" → 进入检验清单；最后给出安慰剂检验与队列稳健性方案。六步走完，模型选择不再是偏好，而是被节号约束的推导。

**第四层，第四章的逻辑方式矩阵。** 推理方式分演绎、归纳、溯因三种；逻辑样态分链、树、环、网、螺旋、场六种。二者交叉成十八种组合，但 §4.5.2 进一步收敛出九种常用组合链，并给出"逻辑链自动生成规则"——把抽象组合翻译成具体的章节叙事顺序，而不是只贴一个标签。例如"归纳+链"的叙事顺序是：数据 → 模式 → 统计推断 → 因果结论 → 异质性分支 → 多路径交叉验证 → 稳健性；"演绎+树"则是：理论命题 → 可检验的分支假设 → 逐支实证检验 → 分支收敛或证伪 → 命题修正。与之配套的 L1–L6，是六层逻辑决策链，负责把"选了什么逻辑"真正落到"先写什么、后写什么、哪一段承担证伪"。

**真正容易被读丢的，是三组硬链接。** 指引的骨架不是六块内容的简单堆叠，而是三组"严格对照"关系：H1，六层决策树（§3.6）与逻辑决策链（L1–L6）逐层对齐；H2，34 个模型节点与第四章适配矩阵的 34 行一一对应；H3，类型模板与最终语言风格相互锚定。这三组关系是同一份知识在不同维度上的投影，错一处就会前后矛盾。理解了硬链接，才算读懂了这份指引。

## 三、skill 怎么做：把结构变成可追溯的决策逻辑

econpaper-architect 用"双底座"承接这份指引。内容底座是《经济论文撰写指引》本身——类型判断、模板、34 模型、六层决策树、逻辑矩阵、语言风格，全部以节号引用，不得凭印象。执行骨架是《经济论文写作 Agent 使用手册》——S0–S9 对话流程、D-1~D-10 决策卡、A/B/C/D 四类信息分工、生成与自检规则。两个底座合起来，让"依据什么、走到哪一步、谁拍板"全程可回溯。

**双轨流程应对两种起点。** 标准模式是 S0–S9 九阶段对话：破冰总览、研究问题澄清、资料盘点、目标确认、决策分工、逐项决策、大纲确认、逐节生成、自检迭代。每一阶段都产出确认卡，用户说"可以"才算过关，跳步即违规。快通道则面向信息已齐备的使用者：D-1~D-10 十张决策卡仍须全部显式列出，但改为一次汇总、三批出稿（引言综述理论 / 数据实证策略 / 结果稳健结论摘要），保留节级自检。

**决策链 D-1~D-10 是 skill 的核心动作面。** 十张卡片覆盖模板、模型家族、具体模型、数据修正、推断确认、假设检验、稳健性、逻辑方式与样态、语言风格、输出格式。其中 D-2~D-7（即从研究目标到稳健性方案这一段）不靠自由发挥，而是由内置脚本 `decide.py` 裁决——脚本吃进研究目标、识别来源、数据条件、推断目标、关键假设，直接吐出适配模型、不适配模型、替代方案与依据节号。一个典型的调用形如 `decide.py --goal 政策效应 --identification 分批落地 --data 两期面板`，输出会是"推荐交叠 DID / 经典 DID，不适配 RDD（无明确切断点），替代为事件研究（若有多期），依据 §3.6 决策层 2–3"。脚本输出作为推荐项，最终仍由用户确认。也就是说，模型选择的"专业性"来自指引的规则表，而不是来自模型的即兴发挥。

**A/B/C/D 四类信息分工，划定了人机边界。** A 类（研究问题、核心假设、目标期刊、语言、数据模拟授权、代码执行授权）由用户拍板；B 类（模板、模型家族、逻辑方式、语言风格、输出格式）给 2–4 个选项加推荐项由用户选；C 类（具体模型、稳健性方案、逻辑样态、文献补充）提方案加依据由用户确认；D 类（排版、公式渲染、图表生成、参考文献格式）自主处理并告知。这套分工让"哪些必须你定、哪些我可以建议、哪些我直接做"一目了然，避免了 Agent 越权替你做研究判断。

**状态机保证长文可续跑。** 对话进度、已确认决策、待确认项、决策日志都落在 `state.py` 管理的 `state.json` 里；中断后凭文件续跑，不会因为一次超时就把前面的确认全部丢掉。这对动辄十几轮的经济学论文写作尤为重要——它把"过程"也当成了产物。

**三道诚信红线，是 skill 与"胡写 Agent"的分界。** 第一道是硬阻断三条，由 `check.py` 强制把守：存在未标注的模拟数据不放行，正文引用与文献表不一一对应不放行，实证类论文未论证识别假设不放行。第二道是文献三档制：用户提供的文献直接采信；模型基于训练知识推荐的文献，必须标记"⚠️AI推荐·须核验"且不得直接写入最终参考文献表；严禁在正文出现未经用户确认的"某某（2020）发现……"式断言。第三道是模拟数据默认关闭，须用户显式授权才生成，且强制带 `[SIM]` 标记。这三道线写死在 SKILL.md 里，违反即失败。

**模型覆盖分三层，资源按需投放。** Tier1（DID 家族、IV、RDD、PSM、SCM、事件研究、面板固定效应）给完整结构、代码与诊断清单；Tier2（BLP、动态离散选择、CGE、DSGE、ABM、DML、因果森林）给框架与关键诊断；Tier3 其余给清单级卡片。信息不足时按既定降级表处理（无数据先授权再模拟、无文献推脉络并标待核验、无结果给示例并标需替换），且每一步强制标注，不靠沉默假设蒙混。

**边界意识贯穿始终。** skill 明确不碰纯润色、降重、格式转换——这些交给下游的 academic-paper；也不覆盖行业、市场、投资类研报——那属于 research-report-standard。它的主权让渡也很清醒：研究问题、核心假设、目标期刊、个人偏好属 A 类决策，永远由用户拍板；自主度被定为"中度"，任何自主建议都必须标注依据格式。

## 四、它是怎么被造出来的：把一份指引，训成一种能力

把近四万五千字的指引连同它的执行手册，当作不可篡改的底座，是整个过程的第一性约束。原文按章节保真切分存档，决策表做到百分之百保真而非压缩改写——这意味着 skill 之后引用的每一个节号，都能回到底本逐字核对。这种"依据可回溯"不是附加功能，而是架构的前提。

从通用 Agent 到专业架构师，中间经过不止一轮设计确认。分包结构怎么定、依赖策略取自包含还是外挂、与已有学术写作 skill 如何划界、文献与模拟数据怎么守红线、快通道在什么条件下启用、默认语言与底本存档放哪、计量代码以谁为主——这些不是实现细节，而是决定 skill 会不会"跑偏"的阀门。它们被一项项确认下来，而不是被默认填上。

市场上没有现成可复用的同类能力，于是走自研。落地用 skill 创建工具，配套冒烟测试：用一个样例（最低工资与青年就业、省级面板、交叠 DID）逼出决策引擎的正确裁决，再让自检脚本对坏稿触发全部硬阻断、对修好稿归零。通过后打包成可直接分发的压缩包。

同一份指引还被另做成一套彼此严格关联的思维导图（M0 导航总览加 M1–M7 内容图，正好把三组硬链接 H1/H2/H3 画成可看的连线），以及一套适配手机端的公众号可展开卡片——知识被沉淀成了不止一种形态，但源头都指回同一份指引。

## 五、边界与局限：它不代替你做的事

说清楚能力，也要说清楚它不做什么。第一，它不替代润色、降重、格式转换，这些明确交给下游 skill。第二，它不覆盖行业与市场研报，那是另一条专业管线。第三，本机没有 Stata/R 计量环境，所以 skill 生成代码加运行说明，而不臆造运行结果——这是红线，不是遗憾。第四，指引未覆盖的情形，skill 会明确说"指引未覆盖"，并给替代方案，绝不凭偏好臆断。第五，它的自主度是"中度"：可以强烈建议，但 A 类决策（研究问题、核心假设、目标期刊）永远在你手里。

这些边界不是功能的残缺，而是可信的前提。一个会在你没授权时编造文献、伪造结果、擅自改研究问题的 Agent，再"能写"也不可用。

## 六、结语：Agent 的价值在"决策可追溯"

回到开头的那个事实——论文的坑大多在动笔之前。econpaper-architect 做的事，是把一份写作指引从"被人读"变成"被调用"：每一次模型选择都有规则表支撑，每一步决策都有确认卡留痕，每一条依据都能回到原文章节。它不替你做研究，但让你做的每一个前置决策，都站得住、查得清、改得动。

把方法论沉淀为可复用的决策内核，而不是又一个句子生成器——这大概就是这份指引值得被做成 Agent 的原因。
